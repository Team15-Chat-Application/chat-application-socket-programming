# Working product delivery — 28 October 2026

This describes current source and actual execution on 28 October. It supersedes missing-feature statements in older dated snapshots while retaining their original dates. Sprint 1's one-minute recording was made after 23 October and is late delivery.

## Architecture

The same-origin client uses REST accounts and Socket.IO rooms. The Node runtime connects the existing owner-authored authentication/messaging modules to persistent rooms/history, presence and the client. Python implements the equivalent public interface independently. SQLite stores users, bcrypt passwords, revocable sessions, rooms, messages and receipts using parameterised SQL. Every incoming socket event validates JWT/session state. Live membership counts distinct users, including multiple-tab cases.

Messages are persisted before broadcast, then marked Delivered after dispatch. Explicit recipient read events store idempotent per-user receipts. Group status becomes Read when at least one recipient reads it; `readBy` retains recipients. This does not imply everybody read the message or that dispatch proves every remote endpoint received it. History returns the last 50 in chronological insertion order. Database state survives real process restarts; live membership is rebuilt by reconnecting clients.

Presence is room-scoped; typing debounces at 500 ms and expires after 1.5 seconds. The client tracks inactive-room unread badges. Rendering uses DOM text nodes; sanitised entities are decoded once into text rather than executable HTML. JWTs remain in page memory. Transient reconnection rejoins rooms.

## Actual execution

- **249/249 Node tests** across 17 suites; **255/255 Python tests**; **2/2 Chromium browser tests**.
- Node build and both actual launchers pass. Real REST credentials/WebSocket transport and restart checks pass for both backends.
- Load: 50 distinct users, 100 connections, 30 messages, 1,500 receiver observations. Receiver p90 **10.4376 ms**, maximum **42.9209 ms**; persistence maximum **2.4949 ms**. Accounts are seeded through the real account service to avoid conflating the 5/IP login limit with socket capacity. These are local-host measurements.
- TLS: 1.3 and explicit 1.2 negotiate; real credentials authenticate WSS. Plaintext and legacy TLS fail. Only the generated local certificate is explicitly trusted by the test.
- Videos are genuine Chromium captures of the running product, trimmed/re-encoded to the required lengths. Playback, dimensions and duration are checked. No invented demonstration frames are used.

See `evidence/2026-10-28/` for technical JSON and actual UI screenshots. Hosted CI must be verified at its actual head; local results are not hosted CI claims.
